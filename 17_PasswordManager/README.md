# パスワード管理ツール

## 学習ポイント
暗号化(System.Security.Cryptography)、SQLite

## 概要
サイト名・ユーザー名・パスワードを暗号化して保存・管理するパスワード管理ツール。マスターパスワードでロックし、正しいマスターパスワードを入力しないと保存済みパスワードを復号できない。

## 実装メモ
- 鍵導出は`Rfc2898DeriveBytes.Pbkdf2`(PBKDF2/SHA-256、10万回反復)を使い、マスターパスワードとランダムなソルト(16byte、初回にDBへ保存)からAES-256鍵を導出する
- 暗号化はAES-CBC。エントリごとにランダムIV(16byte)を生成し、`IV + 暗号文`をBase64化してDBに保存する(復号時は先頭16byteをIVとして取り出す)
- マスターパスワードの正誤判定は、初回セットアップ時に既知の固定文字列を導出鍵で暗号化した「検証用値」をDBに保存しておき、次回起動時に入力されたパスワードから導出した鍵で検証用値を復号して一致するかどうかで行う。復号失敗(誤った鍵によるパディング不正等)も「不一致」として扱う
- 復号後の平文パスワードはセッション中のみメモリ上に保持し、DBには常に暗号化した状態で書き込む
- `SqlitePasswordRepository`はエントリ(Entries)テーブルとマスターキー設定(Settings、1行のみ)テーブルを同一DBファイルで管理し、`IPasswordEntryRepository`と`IMasterKeyStore`の両方を実装する
- `System.Windows.Controls.PasswordBox`はセキュリティ上`Password`プロパティをバインドできないため、コードビハインドで`PasswordChanged`イベントからViewModelのプロパティへ反映し、逆方向(選択したエントリの内容をフォームに反映する場合など)は`PropertyChanged`を購読してViewModel側の変更をPasswordBoxへ書き戻す
- 一覧のパスワードは既定でマスク表示とし、行ごとの表示/非表示切り替えボタン(`IsPasswordVisible`をトグル)とクリップボードコピーボタンを用意した
- UI Automationで実機を操作し、以下を確認済み:
  - 初回起動時にマスターパスワードを新規設定するとロックが解除されること
  - エントリを追加すると一覧に反映され、パスワードは既定でマスク表示、表示切替ボタンで平文表示に切り替わること
  - コピーボタンでクリップボードに復号済みパスワードがコピーされること
  - 一覧から選択した内容が入力フォームに反映され、更新・削除が正しく反映されること
  - アプリを再起動しても初期設定済みの状態が保持され、誤ったマスターパスワードではロックが解除されずエラーメッセージが表示されること、正しいマスターパスワードでは保存済みのデータ(削除後の状態)が正しく復号されて表示されること
