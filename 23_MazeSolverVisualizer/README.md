# 迷路生成&探索ビジュアライザ

## 学習ポイント
迷路自動生成(棒倒し法/穴掘り法)、経路探索(BFS/DFS/A*/ダイクストラ)、アルゴリズム可視化

## 概要
迷路を自動生成し、複数の探索アルゴリズム(BFS/DFS/ダイクストラ/A*)で解を探す過程をアニメーション表示するビジュアライザ。

## 実装メモ
- 迷路データ構造は`Maze`クラスが「セル間が通路として繋がっているか」を`Dictionary<(int,int), HashSet<(int,int)>>`(隣接リスト)で保持する設計とした。壁の有無ではなく通路の有無を直接表現することで、生成・探索の両方から扱いやすくした
- 迷路生成は棒倒し法ではなく穴掘り法(再帰的バックトラッカー)を採用。`Random`を外部から注入できるようにし、テストでは同一シードから同一迷路が再現されることと、全セルが起点から到達可能(スパニングツリー性)であることを検証した
- 探索アルゴリズムは`IMazeSolver`共通インターフェースでBFS/DFS/ダイクストラ法/A*(マンハッタン距離ヒューリスティック)を実装。経路復元ロジック(`cameFrom`辞書からの逆算)は4アルゴリズム共通で使えるため`MazeSolverPathBuilder`に切り出した
- ダイクストラ法とA*は`PriorityQueue<TElement,TPriority>`(.NET標準)を使用。本アプリの迷路は全辺のコストが1のスパニングツリーのため、BFS/ダイクストラ/A*が求める最短経路自体は一致するが、**探索順序(訪問セル数)が異なる**点を可視化の見どころとした
- アニメーション表示はViewModelが「訪問順序リスト」と「現在の再生位置(ステップindex)」のみを保持し、`DispatcherTimer`によるステップ進行と実際の描画(Canvas上のセル色分け・壁の線描画)はView層(コードビハインド)が担う
- `AnimationStepIndex`が0のまま(未探索状態)でリセット/再生成された場合の再描画漏れを防ぐため、`22_GameOfLife`と同様に`MazeChanged`イベントを明示的に用意した
- **UI Automationでの気づき(`22_GameOfLife`からの継続)**: `Canvas`は既定でAutomationPeerを持たずAutomationIdで発見できないため、隣接するツールバー要素の座標から位置を逆算する手法で対応した。また、`ComboBox`のリスト項目はUI Automationの`Name`プロパティが(表示に使う`DisplayMemberPath`ではなく)バインドしたオブジェクトの`ToString()`になることを確認した(表示上は正しく`Name`プロパティの値が見えるが、自動化スクリプトから項目を検索する際は要注意)
- UI Automationで実機を操作し、以下を確認済み:
  - 迷路が生成され、壁のパターンが再生成のたびに変わること
  - BFSで探索を実行すると、スタートから同心円状に広がる効率的な探索(訪問セル数が少ない)で最短経路(オレンジ)が求まること
  - アルゴリズムをDFSに切り替えて探索すると、迷路のほぼ全域を深く探索してから(訪問セル数が非常に多い)ゴールに到達する、遠回りな経路が求まること。BFSとの探索特性の違いが視覚的に明確に確認できた
