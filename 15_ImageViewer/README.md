# 画像ビューア

## 学習ポイント
ファイルダイアログ、Image表示、サムネイル一覧

## 概要
フォルダ内の画像をサムネイル一覧表示し、選択した画像を拡大表示するビューア。

## 実装メモ
- サムネイルの重い処理(ファイルデコード)はUIをブロックしないよう`Task.Run`内で`BitmapImage`を`DecodePixelWidth`指定で縮小デコードし、`Freeze()`してスレッド間で安全に受け渡す設計にした(WPFの標準的な非同期画像読み込みパターン)
- 大きなプレビューは`SelectedImage.FilePath`を`Image.Source`に直接バインドし、WPF標準の`ImageSourceConverter`による文字列パス→`BitmapImage`の自動変換でフル解像度表示する
- フォルダ選択は`IFolderPicker`抽象を介し、`.NET 8+`で追加された`Microsoft.Win32.OpenFolderDialog`を利用。ViewModelのテストでは実際にダイアログを開かず固定パスを返すフェイクで検証した
- `ImageFileScanner`(フォルダ内の画像列挙)は実一時フォルダにファイルを作成してテストした。ファイルシステム操作は高速・決定的なため実I/Oでの検証を採用(ネットワークのような外部要因の不確実性が無いため)
- `BrowseFolderCommand`は`AsyncRelayCommand`とし、フォルダ選択後の画像列挙・サムネイル読み込みを非同期化。画像取得後は最初の画像を自動選択し、`Previous`/`NextCommand`で前後の画像に切り替える(先頭/末尾では該当コマンドを無効化)
- **UI Automationでのフォルダ選択ダイアログ自動操作の難しさ**: `OpenFolderDialog`(モダンなシェルベースのダイアログ)はアドレスバーへの`Ctrl+L`+パス入力+Enterでは「検索条件に一致する項目はありません」という検索結果になってしまい、ナビゲーションとして機能しなかった。また、ダイアログのナビゲーションペイン(サイドバーの「ピクチャ」等)やアドレスバーの内部コントロールはUI Automationの`Descendants`探索で正しく取得できないことがあった。最終的に、ダイアログの既定表示フォルダ(ドキュメント)に検証用画像を直接配置し、パス入力・フォルダツリー操作を行わずに「フォルダーの選択」ボタンをそのままクリックする方式で実機確認を行った
- 実機でのUI Automation確認内容: フォルダ選択ダイアログから画像フォルダを選択→サムネイル一覧(3件、画像でない`.txt`ファイルは除外)が表示→最初の画像が自動選択・拡大表示→「次へ」ボタンでプレビュー・サムネイル選択が連動して切り替わる→先頭画像で「前へ」ボタンが無効化されることを確認済み
