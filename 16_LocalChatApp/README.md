# 簡易チャットアプリ(ローカルSocket)

## 学習ポイント
TCP/IP通信、非同期処理

## 概要
ローカルネットワーク内でTCPソケット通信を行う簡易チャットアプリ(サーバー/クライアント)。1対1接続のみに対応する。

## 実装メモ
- サーバーは`TcpListener`で1件のクライアント接続を待ち受け(`WaitForConnectionAsync`)、クライアントは`TcpClient`でサーバーに接続する(`ConnectAsync`)。接続確立後はどちらも同じ`TcpChatConnection`(改行区切りテキストを`StreamReader.ReadLineAsync`/`StreamWriter.WriteLineAsync`で非同期送受信)にラップされ、対等にメッセージをやり取りする
- `TcpChatConnection`は生成と同時にバックグラウンドで読み取りループを開始し、1行受信するたびに`MessageReceived`イベントを発火。接続断・通信エラー発生時は`Disconnected`イベントを発火してループを終了する
- 受信イベントはバックグラウンドの読み取りスレッドから発火するため、`IUiDispatcher`抽象(実装はWPFの`Dispatcher.Invoke`をラップ)を介してUIスレッドの`ObservableCollection`を安全に更新する。ViewModelのテストでは同期実行するフェイクを使い、実際のWPF Dispatcherなしで検証した
- `TcpChatConnection`自体は実際にループバック(127.0.0.1、OSが割り当てる空きポート)で2つの`TcpClient`を接続させ、実際の送受信・切断検知をテストした(外部ネットワーク非依存で高速・決定的)
- 通信エラー・相手からの切断時は`Disconnected`イベント経由で`IsConnected`をfalseに戻し、チャット欄にシステムメッセージ(「接続が切断されました。」)を表示する。自分から`DisconnectCommand`で切断した場合はイベントを事前に解除してから`Close()`することで、システムメッセージの二重表示を防いでいる
- UI Automationで実機を操作し、以下を確認済み:
  - 実際に2つのプロセス(サーバー役・クライアント役)を起動し、同一マシン上でTCP接続(127.0.0.1)を確立できること
  - クライアント→サーバー、サーバー→クライアントの双方向でメッセージが正しく送受信され、チャット欄に自分のメッセージは右寄せ、相手のメッセージは左寄せで表示されること
  - サーバー側から切断すると、クライアント側で「接続が切断されました。」というシステムメッセージが表示され、接続設定欄が再度操作可能になること
